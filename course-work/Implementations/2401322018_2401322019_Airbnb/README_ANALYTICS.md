# Airbnb — аналитичен доклад

## Какво съдържа проектът

Готов интерактивен аналитичен доклад за университетската курсова работа на тема Airbnb. Използвани са демонстрационните данни от `database/02_seed_data.sql` и същите правила за фактите и измеренията, както в `warehouse/02_load_warehouse.sql`.

## Бързо отваряне

Отворете `dashboard/index.html` в Chrome, Edge или Firefox. HTML файлът работи без интернет и допълнителен сървър, когато `plotly.min.js` е в същата папка. Изборите за държава, град, тип имот и година обновяват всички относими визуализации.

В GitHub прегледайте `dashboard/preview.png`; браузърният HTML работи като интерактивен файл след изтегляне или чрез GitHub Pages. GitHub не изпълнява HTML в обикновен изглед на файловете.

## Визуализации

1. Резервации по месец — линейна диаграма.
2. Завършени плащания по град — хоризонтална стълбовидна диаграма.
3. Статуси на резервациите — пръстеновидна диаграма.
4. Средна оценка по град — колонна диаграма.
5. Активни имоти по тип — пръстеновидна диаграма.
6. Приходи по метод на плащане — хоризонтална стълбовидна диаграма.

Четири индикатора обобщават резервации, платени суми, средна оценка и активни обяви.

## Данни

`data/` съдържа CSV експорти на всичките 11 DW таблици с ключове и полета, идентични с предоставените SQL скриптове. Това е фиксирана снимка на примерните данни, а не жива връзка към текущ SQL Server. След нови записи в базата снимката трябва да се генерира отново.

`dashboard/report_data.json` е локален файл с агрегирано описателни полета за трите таблици факти и инвентара от имоти. HTML версията съдържа същите данни, вградени директно.

## Изграждане на Power BI Desktop версия

1. Изпълнете SQL скриптовете в `database/`, след това `warehouse/01_create_warehouse.sql` и `warehouse/02_load_warehouse.sql` в SQL Server.
2. Отворете Power BI Desktop → Get Data → SQL Server. Server: `localhost` или действителното име на инстанцията. Database: `AirbnbCoursework`. Data connectivity mode: Import.
3. Изберете всички 11 таблици от схемата `dw` (`DimDate`, `DimGuest`, `DimHost`, `DimProperty`, `DimLocation`, `DimPaymentMethod`, `DimBookingStatus`, `DimPaymentStatus`, `FactBookings`, `FactPayments`, `FactReviews`). Алтернативно `powerbi/queries/` съдържа отделна M заявка за всяка таблица.
4. От Model view свържете таблиците по `powerbi/model_relationships.csv`: едно към много (`1:*`) и еднопосочно филтриране от измеренията към фактите. Трите роли на датата в `FactBookings` изискват само `BookingDateKey` да е активна; другите две — неактивни.
5. В Modeling → New measure създайте всяка от мерките в `powerbi/measures.dax`. Файлът е колекция от определения, а не скрипт, който Power BI Desktop изпълнява наведнъж.
6. Изградете визуализациите по `powerbi/report_layout.md` и запишете Power BI файла като `Airbnb_Analytics.pbix` в същата папка `powerbi/`.

Няма готов `.pbix` файл в този комплект — Power BI Desktop трябва да запише нативния отчет. Работещият готов отчет е `dashboard/index.html`.

## Валута

В базовия модел колоните за суми нямат поле за валута. В уеб визуализацията сумите са представени като условни парични единици. При реална продукционна система е необходим атрибут за валута и/или курсове.

## Логика на показателите

Брой резервации включва всички статуси и се отчита по `BookingDateKey` (датата на създаване). Приходи включват само плащания със статус `Completed` и се отчитат по `PaymentDateKey`. Отзивите се групират по `ReviewDateKey`. При филтриране по година всяка метрика използва съответната си дата на събитие, а брой обяви няма времеви филтър, защото инвентарът не е историзиран в DW модела. Суми от резервации и плащания не трябва да се събират заедно.
