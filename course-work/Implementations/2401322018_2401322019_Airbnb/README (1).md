**Тема:** моделиране на платформа за краткосрочно настаняване от типа на Airbnb  
**База данни:** Microsoft SQL Server (T-SQL)  
**Моделиране:** Chen, Crow's Foot и UML Database Notation  
**Анализи:** Data Warehouse, Power BI файлове и интерактивен HTML доклад

## 1. Представяне на проекта

Проектът разглежда основните данни и процеси в платформа за краткосрочно отдаване на имоти. Потребител може да публикува имот като домакин или да резервира настаняване като гост. За имотите се съхраняват местоположение, тип, капацитет, цена и удобства. Системата моделира създаването на резервации, плащанията и отзивите след престой.

Реализирани са два свързани слоя:

- **Оперативна релационна база** — таблици, ограничения, индекси и SQL логика за резервации, плащания и отзиви.
- **Аналитичен слой (Data Warehouse)** — таблици факти и измерения за справки по периоди, имоти, локации, статуси и начини на плащане.

Проектът е учебен модел, а не копие на реалната информационна система на Airbnb. Записите са демонстрационни.

## 6. Инсталиране и стартиране на базата данни

### 6.1. Свързване към SQL Server

1. Стартирайте **SQL Server Management Studio**.
2. В прозореца **Connect to Server** изберете **Database Engine**.
3. Въведете адреса на вашата работеща SQL Server инстанция. В зависимост от инсталацията може да е `localhost`, `.\SQLEXPRESS` или друго име.
4. Изберете **Windows Authentication** или предоставените SQL Server данни за вход.
5. Натиснете **Connect**, после **New Query**.

### 6.2. Създаване и попълване

### 6.3. Кратка проверка в SSMS

След изпълнението отворете нова заявка и изпълнете:

```sql
USE AirbnbCoursework;
GO
SELECT COUNT(*) AS TotalUsers FROM dbo.Users;
SELECT COUNT(*) AS TotalProperties FROM dbo.Properties;
SELECT COUNT(*) AS TotalBookings FROM dbo.Bookings;
SELECT COUNT(*) AS TotalPayments FROM dbo.Payments;
```

При непроменените примерни данни се очакват **20 потребители, 18 имота, 49 резервации, 47 плащания и 24 отзива**. Записите във всяка от трите таблици факти трябва да съвпадат по брой със съответната оперативна таблица.

## 7. Структура и бизнес логика на оперативната база

### 7.1. Таблици

| Таблица | Предназначение |
| --- | --- |
| `Users` | Потребители — гости и домакини |
| `Countries` | Държави |
| `Cities` | Градове и принадлежност към държава |
| `PropertyTypes` | Категории имоти |
| `Properties` | Обяви за имоти, домакин, адрес, цена и капацитет |
| `Amenities` | Каталог на удобствата |
| `PropertyAmenities` | Свързваща таблица за удобства на имоти (M:N) |
| `Bookings` | Резервации, дати, брой гости, цена и статус |
| `Payments` | Плащания по резервации |
| `Reviews` | Оценки и коментари след престой |

Използвани са първични и външни ключове, `UNIQUE` и `CHECK` ограничения, както и индекси за често използваните заявки. Връзката много към много между имоти и удобства е нормализирана чрез `PropertyAmenities`.

### 7.2. Съхранени процедури

- `dbo.sp_CreateBooking` — създаване на резервация след проверки за валидни дати, капацитет и заетост.
- `dbo.sp_RecordPayment` — записване на плащане и потвърждаване на резервация.
- `dbo.sp_CancelBooking` — отказ на допустима резервация.
- `dbo.sp_CompleteStay` — приключване на потвърден престой.
- `dbo.sp_SearchAvailableProperties` — търсене на свободни имоти по град, дати и брой гости.

Пример за **справка без промяна на данни**:

```sql
USE AirbnbCoursework;
GO
EXEC dbo.sp_SearchAvailableProperties
    @CityID = 1,
    @CheckInDate = '2027-03-01',
    @CheckOutDate = '2027-03-05',
    @GuestCount = 2;
GO
```

### 7.3. Функции

- `dbo.fn_GetBookingNights` — брой нощувки за резервация.
- `dbo.fn_GetPropertyAverageRating` — средна оценка на имот.
- `dbo.fn_GetPropertyRevenue` — приходи от успешно приключили плащания за имот.

Пример:

```sql
USE AirbnbCoursework;
GO
SELECT dbo.fn_GetBookingNights(1) AS Nights;
SELECT dbo.fn_GetPropertyAverageRating(1) AS AverageRating;
SELECT dbo.fn_GetPropertyRevenue(1) AS PropertyRevenue;
GO
```

### 7.4. Тригери

- `dbo.trg_Bookings_Validate` — валидиране на резервациите и предотвратяване на недопустими припокривания.
- `dbo.trg_Payments_Validate` — контрол върху допустимите плащания.
- `dbo.trg_Reviews_Eligibility` — ограничения за публикуване на отзиви.

### 7.5. SQL изгледи

- `dbo.vw_PropertyOverview` — обща информация за имотите.
- `dbo.vw_MonthlyRevenue` — агрегирани приходи по месеци.

## 8. Data Warehouse

Data Warehouse е реализиран в SQL Server схемата **`dw`** в базата **`AirbnbCoursework`**. Използва схема с общи измерения, свързани с няколко фактни таблици.

**Факти (3):** `dw.FactBookings`, `dw.FactPayments`, `dw.FactReviews`.

**Измерения (8):** `dw.DimDate`, `dw.DimGuest`, `dw.DimHost`, `dw.DimProperty`, `dw.DimLocation`, `dw.DimPaymentMethod`, `dw.DimBookingStatus`, `dw.DimPaymentStatus`.

Фактите съхраняват показатели като брой резервации, нощувки, стойност на резервации, суми на плащания и оценки. Измеренията дават възможност за анализ по дата, имот, град, домакин, гост, начин на плащане и статус.

**Зареждане:** `warehouse/02_load_warehouse.sql` извлича данните от таблиците `dbo`, попълва измеренията и след това фактите. Скриптът използва транзакция и може да се изпълни повторно за **пълно опресняване** на DW. Това е презареждане, а не инкрементален ETL процес.

**Проверка:** `warehouse/03_validate_warehouse.sql` сравнява броя и част от ключовите стойности с оперативните таблици. При несъответствие подава SQL грешка.

**Физически модел:** [Data Warehouse диаграма](diagrams/data_warehouse.png) · [Отвори редактирания модел](diagrams/data_warehouse.drawio)

### 9.2. Power BI Desktop версия

В папка `powerbi/` са включени заявки, връзки между таблиците, мерки и описание на страницата на отчета. За да се създаде нативен Power BI файл:

1. Изпълнете стъпките от **раздел 6**, включително Data Warehouse.
2. Стартирайте **Power BI Desktop → Home → Get data → SQL Server**.
3. Посочете **Server**: вашата SQL Server инстанция (например `localhost` или `.\SQLEXPRESS`), **Database**: `AirbnbCoursework` и **Import** режим.
4. Заредете всичките 11 таблици от схемата `dw` — 8 измерения и 3 факта.
5. В **Model view** създайте връзките, описани в `powerbi/model_relationships.csv`: тип **1 към много (1:*)**, еднопосочно филтриране от измерения към факти. За `FactBookings` връзката с `DimDate` чрез `BookingDateKey` е активна; тези чрез `CheckInDateKey` и `CheckOutDateKey` са неактивни.
6. В **Modeling → New measure** добавете мерките **една по една** от `powerbi/measures.dax`. Това е текстов набор от дефиниции, а не файл за автоматично импортиране на всички мерки наведнъж.
7. Изградете шестте визуализации по `powerbi/report_layout.md` и задайте съответните оси, показатели и филтри.
8. Изберете **File → Save as** и запазете нативния отчет като `powerbi/Airbnb_Analytics.pbix`.

**Алтернативно:** CSV таблиците в `data/` могат да се импортират вместо директна SQL връзка. Всяка заявка в `powerbi/queries/` е M код за съответната DW таблица; ако ползвате тези заявки, **сменете** `localhost` с вашето реално име на SQL Server инстанция.

**Важно за предаването:** Подготвените DAX, M, CSV и HTML файлове **не представляват готов `.pbix` файл**. Ако се изисква Power BI като конкретен инструмент, отчетът трябва да бъде създаден и записан в Power BI Desktop. При използване на HTML варианта той трябва да бъде представен като самостоятелен интерактивен аналитичен доклад, а не като Power BI файл.

## 11. Опресняване и ограничения

- **След промени в оперативната база:** изпълнете отново `warehouse/02_load_warehouse.sql`; при SQL-базиран Power BI доклад изберете **Refresh**.
- **CSV и HTML:** това са експорти на първоначалните демонстрационни данни; не се обновяват автоматично при промяна в SQL Server.
- **Валута:** оперативните таблици пазят парични суми, но не и отделен атрибут за валута. При интерпретация на финансовите показатели трябва да се използва обща предварително договорена валута, без да се предполага автоматично конвертиране.
- **Обхват:** проектът демонстрира модел, бизнес правила и анализи; не реализира пълно уеб приложение с регистрация, интерфейс за резервации и реална обработка на банкови плащания.
- **Примерни данни:** всички резултати и контролни стойности са за доставения учебен набор. При добавяне или редактиране на записи съответните числа ще се променят.

2. Покажете логическата диаграма и връзката много към много между `Properties` и `Amenities`.
3. В SSMS покажете оперативните таблици, ограниченията, съхранените процедури, функциите и тригерите.
4. Изпълнете `sp_SearchAvailableProperties` и една от SQL функциите.
5. Покажете трите факта и осемте измерения в DW диаграмата и резултата от `warehouse/03_validate_warehouse.sql`.
6. Отворете интерактивния доклад и демонстрирайте четирите филтъра и шестте графики.
7. Ако е създаден `.pbix` отчет, покажете също Power BI Model view, мерките и визуализациите.
